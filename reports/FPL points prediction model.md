# Build an FPL model that beats FPL Review on minutes

To beat FPL Review you need to beat it on minutes, not on goals. Build a per-component simulator. A team-goals layer anchored to de-vigged betting odds and npxG ratings feeds an explicit minutes model. That model splits each team's goals among its players with shrunk xG and xA shares, then scores every event through the live API's `game_config.scoring`. A multi-period HiGHS MILP on top handles transfers, captaincy and chips. The only independent benchmark (OpenFPL, 2025) shows what to aim at. A public-data ML regression already matched FPL Review on 3+ point returns (RMSE 1.517 vs 1.594 for 3–4 pointers) but lost clearly on zeros (0.818 vs 0.689). The authors put that gap down to FPL Review's expected-minutes projections ([OpenFPL](https://arxiv.org/html/2508.09992v1)). Hauls stay mostly noise for everyone (RMSE about 5.1–5.2 even for the best model), and FPL Review's own best goals model reached only **R² 0.129 against actual goals** ([FPL Review](https://docs.fplreview.com/articles/massive-data/)). The edge that is still open is in minutes, calibration and decision logic, not in predicting hauls. Every piece you need exists as open source: the FPL API (now with Opta xG and DefCon counts), penaltyblog, AIrsenal v2 and the Solio open-fpl-solver. It all fits a `tools/fpl` service on the homelab. Start snapshotting the API now, because no source archives deadline-time flags, prices or odds.

## The scoring rules: what the live API settles and what stays open

The API settles the dispute in the notes. On 25 Oct 2026, `bootstrap-static` `game_config.scoring` returned **goals GKP 10, DEF 6, MID 5, FWD 4**, clean sheets GKP/DEF 4 and MID 1, assists 3, saves 1, penalty saves 5, and `defensive_contribution` {DEF 2, MID 2, FWD 2, GKP 0} ([bootstrap-static](https://fantasy.premierleague.com/api/bootstrap-static/)). The official 2026/27 "Scoring points" table matches it exactly: 10 for a goalkeeper goal ([PL](https://www.premierleague.com/en/news/2174909)). **The 6-point figure is wrong for 2026/27.** It is still unknown whether 2024/25 used 6, but that only matters if you re-score old seasons, and that is the reason to read point values from `game_config` per season rather than hard-coding them.

| Component | GK | DEF | MID | FWD | Status |
|---|---|---|---|---|---|
| Appearance 1–59 / 60+ min | 1 / 2 | 1 / 2 | 1 / 2 | 1 / 2 | PL table |
| Goal | 10 | 6 | 5 | 4 | API + PL agree |
| Assist | 3 | 3 | 3 | 3 | API + PL agree |
| Clean sheet (60+ min) | 4 | 4 | 1 | 0 | API + PL agree |
| Saves | 1 per 3 | – | – | – | Value from API; "per 3" from PL table |
| DefCon (capped at 2) | – | 2 at 10 CBIT | 2 at 12 CBIRT | 2 at 12 CBIRT | Points from API; thresholds from PL articles |
| Goals conceded | −1 per 2 | −1 per 2 | – | – | PL table |
| Yellow / red, own goal, pen miss | −1 / −3, −2, −2 | same | same | same | PL table |
| Bonus | 3/2/1 by BPS rank, ties shared | | | | PL table |

The API notes recorded per-event point values, not thresholds. Read the save divisor (3), the DefCon thresholds (10 and 12) and the goals-conceded divisor (2) from the same `game_config` object when you build the scorer, before treating them as confirmed. The thresholds come from official PL articles ([PL 2025/26](https://www.premierleague.com/en/news/4362211)), and FF Scout reports "no threshold changes" for 2026/27 ([FFS](https://www.fantasyfootballscout.co.uk/2026/07/20/fpl-2026-27-5-rule-changes-new-features-announced)). One blog's claim that the full-back threshold is "under review" has no figures behind it and is unconfirmed ([Onside](https://onsidearena.com/tips/fpl-rule-changes-2026-27)).

Three rule areas are still unresolved. First, the **2026/27 BPS values** come from FF Scout and Fantasy Football Fix, not a PL table: no BPS for being tackled, CBI at 1 BPS per 3 (was per 2), and goalkeeper saves at 2 plus 1 inside the box plus 1 for a big chance ([FFS](https://www.fantasyfootballscout.co.uk/2026/07/20/fpl-2026-27-5-rule-changes-new-features-announced); [Fix](https://www.fantasyfootballfix.com/blog-index/fpl-2026-27-new-rules/)). Apply them on top of the April 2026 table ([PL BPS](https://www.premierleague.com/en/news/106533)) and recalibrate the bonus cut-offs on 2026/27 matches. Second, **selling-price rounding**: FF Scout and the solver code (`purchase + diff // 2`) say round down, but one PL article says "rounded up" ([FFS](https://www.fantasyfootballscout.co.uk/2026/07/20/how-do-fpl-price-changes-work); [PL](https://www.premierleague.com/en/news/2858775)). Use floor, and check it against your own squad's `selling_price`. Third, the **11 reclassified players** were never named, so take positions from `element_type` and never from articles. The **first-half chip deadline** is settled: the official date is GW19, 13:30 GMT, Sat 2 Jan 2027. A third-party guide's Fri 1 Jan date is wrong ([PL chips](https://www.premierleague.com/en/news/4679879/whats-happening-with-fpl-chips-in-202627)).

## Team goals come from the market for next week and from fitted ratings after that

The market sets the next fixture. De-vigged closing odds carry more information about team strength than results do ([Wunderlich](https://fis-db.dshs-koeln.de/ws/portalfiles/portal/6465170/Dissertation_Wunderlich.pdf)), and no goals-only model beats them. **De-vig each market with the power, Shin or odds-ratio method**, since the basic proportional method "tends to be the least accurate" ([implied](https://cran.r-project.org/web/packages/implied/vignettes/introduction.html)). penaltyblog offers all of them through `calculate_implied` ([penaltyblog](https://penaltyblog.readthedocs.io/en/latest/implied/implied.html)). Then solve each fixture for the (λ_home, λ_away) pair whose Dixon-Coles score matrix reproduces the de-vigged 1X2 and over/under 2.5 probabilities. Over/under fixes only the total; 1X2 is needed to split it between the teams ([opisthokonta](https://www.r-bloggers.com/2020/09/expected-goals-from-over-under-odds/)). Fix ρ at a league-fitted value and optimise in log space. A team's clean-sheet probability is then the zero column of the matrix.

Odds rarely go beyond the next gameweek, so GW+2 to GW+8 need team ratings. Fit attack, defence and home terms to the market-implied λs of recent fixtures. Fitting to the market's expected goals instead of results gives more stable ratings: Leicester 2015/16 looked average in the odds-based fit and much stronger in the results-based one ([opisthokonta](https://www.r-bloggers.com/2019/01/expected-goals-from-bookmaker-odds/)). Fit a second Dixon-Coles model to npxG, with a penalty term and time decay. Dixon and Coles' fitted ξ works out to about **0.0019 per day, a half-life of about a year** ([arXiv 2605.16066](https://arxiv.org/pdf/2605.16066)). Tune your own value by rolling-origin log-loss, because xG ratings and market ratings will want different decays. Blend the two in log space, with the weight chosen out of sample, and shrink toward the mean as the horizon grows. Bivariate, negative-binomial and dynamic Bayesian variants bring small and inconsistent gains on EPL data and were never compared against odds ([arXiv 2508.05891](https://arxiv.org/html/2508.05891v1)), so they are not worth the complexity. Estimate home advantage from recent fan-attended seasons rather than hard-coding a pre-2020 value. The post-Covid evidence conflicts, and the last four seasons were not verified ([LCP](https://www.lcp.com/media-centre/2020/12/covid-19-and-var-decimate-home-advantage-in-football-leagues-across-europe)).

Getting the data as a UK user is the harder part. Match odds are cheap: The Odds API is free for 500 credits a month and $30 a month for 20K ([the-odds-api](https://the-odds-api.com/)). Betfair's delayed app key works straight away, while the live key costs a one-off £499 ([Betfair](https://support.developer.betfair.com/hc/en-us/articles/115003864651-How-do-I-get-started)). Pinnacle closed its public API on 23 July 2025 ([odds-api.io](https://odds-api.io/blog/pinnacle-api-shutdown-alternatives)). Player props are scarce: The Odds API has EPL anytime-scorer, assist, shots and card markets, but **"coverage is currently limited to US bookmakers"** ([Odds API markets](https://the-odds-api.com/sports-odds-data/betting-markets.html)). Treat props as a calibration anchor when they appear, normally 1–3 days out, and not as a core input. Turn an anytime price p into a rate with λ = −ln(1 − p). Then normalise all of a team's player λs to the team's market λ instead of de-vigging each price on its own. Overround is not a margin in multi-winner markets ([OddsPapi](https://oddspapi.io/blog/?p=3086)), and the low-margin 1X2 market is the better anchor. That normalisation is the notes' own proposal, not an established method. For xG, use the FPL API itself: it serves Opta xG, xA and xGC per player-match. FBref lost its Opta advanced stats on **20 January 2026** ([The IX](https://www.theixsports.com/the-ix-soccer/fbrefs-loss-advanced-stats-womens-soccer-data-accessibility/)), so Understat via soccerdata is the long-history source ([soccerdata](https://soccerdata.readthedocs.io/en/latest/)).

## Every scoring component runs through one match simulation

The minutes model matters most. Model P(start), the minutes distribution given a start, and P(sub appearance) from a decayed per-gameweek log, then cap or override with `chance_of_playing_next_round`. Moving from season-average minutes to that structure **cut minutes error by about 23%** at 1–3 gameweeks ahead in one open project ([Gaffer PR #30](https://github.com/M9chaelangelo/Gaffer/pull/30)). Model P(60+ | start) as logistic in minutes per start: a player averaging 64 minutes per start is hooked before 60 far more often than one averaging 88 ([fpl-machine](https://github.com/kelihh/fpl-machine)). This is where FPL Review's lead comes from. Its xMins is a 1,000-simulation average that covers rotation, injury and news, refreshed hourly, checked by a human after press conferences and re-run at the deadline ([FPL Review xMins](https://docs.fplreview.com/the-model/projections/xmins/)). To match it you need a manual override table in your dashboard, plus a European-midweek congestion feature. The notes found no figures for how much congestion moves start probability, so fit that effect yourself. When a start is confirmed, re-condition the per-90 rates and clean-sheet eligibility too, not just minutes ([best-ball-pl #216](https://github.com/wulke/best-ball-pl/issues/216)).

Attacking returns follow AIrsenal's design. Split simulated team goals among players with Dirichlet-shrunk shares of team npxG and xA, scaled by minutes on the pitch, and add a separate penalty term for designated takers ([AIrsenal](https://raw.githubusercontent.com/alan-turing-institute/AIrsenal/main/docs/how-it-works.md)). Shrink finishing skill to almost nothing. Even the top-10 finishers sit only about +0.23 to +0.35 log-odds above xG, with wide credible intervals ([pena.lt](https://pena.lt/y/2025/10/01/a-better-way-to-measure-finishing-skill/)). Recent goals over five games predicted *worse* than a basic position-and-fixture model, and recent xG only becomes useful after about 20 games ([FPL Review](https://docs.fplreview.com/articles/massive-data/)). The 2025/26 assist rule now counts rebounds from saved shots and won penalties or free-kicks. The PL estimated it would have added 41 assists in 2024/25, which raises assist rates for shooters ([PL assists](https://www.premierleague.com/en/news/4362187)).

DefCon is a threshold event, so model P(count ≥ 10 or 12), not the mean. Match counts are close to Poisson for defenders (variance/mean about 1.02) but under-dispersed for midfielders (about 0.81), so a Conway-Maxwell-Poisson or binomial fits midfielders better ([fpl-predictor #57](https://github.com/amanwaseem/fpl-predictor/pull/57)). Hit rates belong to centre-backs and defensive midfielders in low-possession teams. Applied to 2024/25, Huijsen hit the threshold in 73.1% of starts and Casemiro in 66.7%, while Everton produced 57 defender hits against the fewest for City, Villa, Arsenal and Chelsea ([The Analyst](https://theanalyst.com/articles/fpl-defensive-contributions-2025-26-best-picks)). Scale the rate by opponent possession and game state. FPL has exposed the raw CBIT and recovery counts only since 2025/26, so DefCon training data covers just over a season ([element-summary](https://fantasy.premierleague.com/api/element-summary/1/)).

For clean sheets, goals conceded and saves, use the conceding team's simulated goals against while the player is on the pitch. The clean sheet needs 60+ minutes and survives a substitution if no goal had been conceded yet ([PL](https://www.premierleague.com/en/news/2174909)). Draw saves from opponent shots on target minus goals in the same draw, so saves and clean sheets carry their natural negative correlation. For bonus, give each player a baseline BPS per 90 re-scored under the 2026/27 rules, add the simulated events, rank within the match and apply the official tie rules. Cards and penalty misses are small terms: a shrunk rate per 90 times expected minutes is enough, as AIrsenal does ([AIrsenal](https://raw.githubusercontent.com/alan-turing-institute/AIrsenal/main/docs/how-it-works.md)). Run about 10⁴ draws per fixture and keep each player's points array. The means drive transfers. The arrays give P(≥10), quantiles and squad variance for captaincy, with teammate, goalkeeper-defender and bonus correlations built in. OpenFPL outputs no distributions at all ([OpenFPL](https://arxiv.org/html/2508.09992v1)).

The "better than FPL Review" plan follows from this. Use the component simulator as the backbone. Optionally stack an OpenFPL-style gradient-boosted residual model on top of the return rates, since that is where direct ML did well. Fall back to market and position priors for players with fewer than five full matches, as FPL Review does ([FPL Review](https://docs.fplreview.com/articles/massive-data/)). This blend is a reasoned bet, not a proven result. Nobody has published how these approaches combine.

## The decision layer is a solved problem: reuse the open solver

Solio's open-fpl-solver (formerly sertalpbilal/FPL-Optimization-Tools) is the de facto standard. It is a deterministic multi-period MILP on HiGHS with binary squad, lineup, captain, vice and bench-slot variables. FT state is a 0–5 integer, there are per-gameweek chip binaries with one chip per week, and Free Hit uses a separate 15-man squad. It reads projections from a CSV ([open-fpl-solver](https://github.com/sertalpbilal/FPL-Optimization-Tools)). Its defaults are a sensible starting point, but they are tuning choices, not derived values: horizon 8, decay 0.9 (GW8 worth about 0.48 of GW1), FT values of 2/1.6/1.3/1.1 for the 2nd to 5th banked transfer, bench weights of 0.03/0.21/0.06/0.002, hit cost 4, and no transfers in the last two horizon weeks. Write your projections in its CSV format and spend your effort on the model.

You can beat the default in three ways. First, derive **bench weights from your own minutes distribution** (P(starter blanks) × P(sub plays)) instead of fixed constants. FPL Review calls fixed autosub weights the main linearisation error and offers a non-linear solver as a cross-check ([FPL Review solvers](https://docs.fplreview.com/the-model/solvers/solver-comparison/)). Second, run 50–200 **randomised re-solves** with noise that grows with minutes uncertainty. The repo scales it by (92 − xMins). Act on the moves that keep coming up, not on a single solve. Third, **value chips by enumeration**: fix each chip in each eligible week and compare objectives, with `iteration_criteria: "chip_gws"` for k-best plans. The 2026/27 rules are two sets of WC/FH/BB/TC, the first used by the GW19 deadline with no carry-over, one chip per week, no Free Hit in GW1, and up to 5 banked FTs ([PL chips](https://www.premierleague.com/en/news/4679879/whats-happening-with-fpl-chips-in-202627)). There is also **no AFCON top-up this season** ([FFS](https://www.fantasyfootballscout.co.uk/2026/07/20/fpl-2026-27-5-rule-changes-new-features-announced)). No blanks or doubles are expected before GW19 ([FF Hub](https://www.fantasyfootballhub.co.uk/articles/fpl-chip-strategy-guide)). It is now GW8, so the first-half chips gain value from fixture swings and single-week mismatches, not doubles. The solver must be forced to spend any unused first-set chips by GW19.

For captaincy, use EV first, then adjust for rank. Effective ownership makes your relative points equal to (your multiplier − EO) × points. A high-EO captain therefore protects your rank, and a differential pays only when you are chasing ([FFS EO](https://www.fantasyfootballscout.co.uk/2021/03/24/what-is-effective-ownership-and-why-is-it-so-widely-talked-about-in-fpl/)). With the simulated arrays you can maximise E[points − Σ EO·points] or P(beat target) directly, which the open solver's mean-only captain term cannot do. Team value hardly matters. The default objective prices £0.1m of selling value at about 0.008 points, and the official nightly price predictor added in 2026/27 shrinks the edge from beating price rises ([PL 2026/27](https://www.premierleague.com/en/news/4679873/all-you-need-to-know-about-changes-to-fpl-for-202627)).

## Homelab build: four containers, snapshots first, judged by walk-forward backtests

The architecture maps onto the repo rules: one `tools/fpl/compose.yaml`, pinned Python images, the template labels and healthcheck, and data in `${APPDATA_PATH}/fpl/`. Cron jobs run through `scripts/cron-run.sh`. An ingest job archives `bootstrap-static` every 1–3 hours as dated Parquet. It also pulls fixtures and `element-summary` after each gameweek, odds daily (props on match-eve), and Understat weekly. Ingest is the first thing to deploy, because flags, prices, `ep_next` and odds are not archived anywhere as they were at the deadline. vaastav's dataset now updates only three times a season, and its `xP` column leaks post-match information ([vaastav](https://github.com/vaastav/Fantasy-Premier-League)). Store the data in DuckDB over Parquet. Run the team and player models on CPU with penaltyblog, numpyro or LightGBM. The notes judge the GTX 970 unfit for modern JAX, and about 700 players a week is small. Reuse AIrsenal v2 (MIT, Dockerised, released 25 Sep 2026; install from source, as PyPI is marked work-in-progress) for its xG team model, Dirichlet shares and minutes code ([AIrsenal](https://github.com/alan-turing-institute/AIrsenal)). Serve a FastAPI or Streamlit dashboard on a free port from the CLAUDE.md table. Check the current versions of penaltyblog, highspy and the solver before pinning; the notes did not verify them.

Evaluate walk-forward by gameweek, with features frozen at the deadline. Report RMSE and MAE by OpenFPL's return categories (zeros, ≤2, 3–4, ≥5). Score event probabilities (60+ minutes, goal, assist, clean sheet, DefCon) with log-loss and calibration plots, and track within-position rank correlation and captain hit rate. Then replay the season through the solver under each model. Your baselines are last-5 average, FPL's `ep_next` and a market-only model. **FPL Review's zeros RMSE of 0.689** is the specific number to beat ([OpenFPL](https://arxiv.org/html/2508.09992v1)). Be honest about what you can measure. OpenFPL's test covered only seven gameweeks, there is no public season-long head-to-head, and Onside's claimed MAE of 1.57 against 1.86 for `ep_next` contains internal inconsistencies ([Onside](https://onsidearena.com/accuracy)). Only about 6.5% of top-10k managers repeated the next season ([FPL Review](https://docs.fplreview.com/articles/top-10k/)), so judge the system on EV and calibration, not your overall rank.

## Conclusion

Three gaps in the field are open to a self-hosted builder. Minutes are where the best commercial model wins, and that comes down to news handling and data engineering more than modelling, so hourly snapshots and a dashboard override table close more of the gap than a fancier learner would. Second, the open solver's linearisations (fixed bench weights, mean-only captaincy) can be replaced with quantities read directly from your own simulation arrays. Third, the new DefCon and BPS rules are only 1.25 seasons old, so everyone's DefCon and bonus estimates are still thin, and a well-calibrated threshold model is a real edge this season.

Two things you cannot fix by building better: no UK-book player props, and no Opta event data beyond what the FPL API serves. Plan to win on calibration rather than information. Verify the remaining rule details (save and DefCon thresholds in `game_config`, 2026/27 BPS values, selling-price rounding) in code against live API responses before the first backtest.
